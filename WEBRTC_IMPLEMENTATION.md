# WebRTC Video Calling Implementation

## Overview
This document describes the WebRTC peer-to-peer video calling implementation using RTCPeerConnection and WebSocket signaling.

## Architecture

### Components
1. **VideoCall.jsx** - React component handling WebRTC and UI
2. **WebSocket Signaling Server** - Backend endpoint at `ws://localhost:8000/ws/call/{session_id}`
3. **STUN Servers** - Google's public STUN servers for NAT traversal

## WebRTC Flow

### 1. Connection Setup
```
Therapist (Offerer)          WebSocket Server          Patient (Answerer)
      |                              |                         |
      |------ Connect to WS -------->|                         |
      |                              |<------ Connect to WS ---|
      |                              |                         |
      |--- getUserMedia() -------->  |                         |
      |<-- Local Stream ----------   |                         |
      |                              |                         |
```

### 2. Signaling Flow
```
Therapist                    WebSocket Server          Patient
    |                              |                      |
    |--- Start Call ------------->|                      |
    |--- Create Offer -----------> |                      |
    |                              |                      |
    |                              |--- Forward Offer -->|
    |                              |                      |--- getUserMedia()
    |                              |                      |--- Create Answer
    |                              |<-- Send Answer ------|
    |<-- Forward Answer -----------|                      |
    |                              |                      |
    |<-- ICE Candidates ---------->|<-- ICE Candidates -->|
    |                              |                      |
    |<============== CONNECTED (P2P) ==================>|
```

### 3. ICE Candidate Exchange
```
Both Peers
    |
    |--- Generate ICE Candidate
    |--- Send via WebSocket
    |--- Receive from WebSocket
    |--- Add to RTCPeerConnection
    |
    |--- Repeat until connected
```


**STUN Servers**: Help discover public IP addresses for NAT traversal

**Capabilities**:
- Captures camera video

#### 1. Offer (Caller → Callee)
```json
{
  "type": "offer",
  "offer": {
    "type": "offer",
    "sdp": "v=0\r\no=- ... [SDP content]"
  }
}
```

#### 2. Answer (Callee → Caller)
```json
{
  "type": "answer",
  "answer": {
    "type": "answer",
    "sdp": "v=0\r\no=- ... [SDP content]"
  }
}
```

#### 3. ICE Candidate (Bidirectional)
```json
{
  "type": "ice-candidate",
  "candidate": {
    "candidate": "candidate:... udp 2122260223 192.168.1.100 ...",
    "sdpMLineIndex": 0,
    "sdpMid": "0"
  }

```

## Key Features

### Local Video Stream
- Captured using `getUserMedia()`
- Displayed in local video element
- Muted for local playback (no echo)
- Tracks added to RTCPeerConnection

### Remote Video Stream
- Received via `RTCPeerConnection.ontrack` event
- Displayed in remote video element
- Automatically plays when tracks arrive

### ICE Candidate Handling
- Generated by RTCPeerConnection
- Sent through WebSocket signaling
- Queued if remote description not yet set
- Applied after remote description is established

### Connection State Management

**States**:
- `idle` - No active call
- `calling` - Call initiated, waiting for connection
- `incoming` - Receiving incoming call
- `connected` - WebRTC connection established
- `ended` - Call terminated

**Events Monitored**:
- `onconnectionstatechange` - Overall connection state
- `oniceconnectionstatechange` - ICE connection state
- `ontrack` - Remote media tracks received

## Error Handling

### Common Errors

1. **Camera/Microphone Permission Denied**
   - Prompt user to allow permissions
   - Display error message

2. **WebSocket Connection Failed**
   - Check backend is running
   - Verify session_id is valid

3. **ICE Connection Failed**
   - STUN server unreachable
   - Firewall blocking UDP traffic
   - May need TURN server

4. **Connection Lost During Call**
   - Network interruption
   - Cleanup and notify user

## Backend Requirements

The backend WebSocket server must:

1. **Accept connections** at `/ws/call/{session_id}`
2. **Relay messages** between peers in same session
3. **Handle signaling** for offer, answer, ICE candidates
4. **Manage sessions** and user presence
5. **Clean up** disconnected clients

### Example Backend Message Relay
```python
@app.websocket("/ws/call/{session_id}")
async def websocket_endpoint(websocket: WebSocket, session_id: str):
    await websocket.accept()
    
    # Store connection
    connections[session_id].append(websocket)
    
    try:
        while True:
            data = await websocket.receive_text()
            message = json.loads(data)
            
            # Relay to other peer in session
            for conn in connections[session_id]:
                if conn != websocket:
                    await conn.send_text(data)
    except:
        connections[session_id].remove(websocket)
```

## Troubleshooting

### No Video/Audio
- Check camera/microphone permissions
- Verify getUserMedia() succeeds
- Check browser console for errors

### Connection Not Establishing
- Verify WebSocket connection open
- Check offer/answer exchange in logs
- Verify ICE candidates being generated
- Test STUN server connectivity

### One-Way Video
- Check firewall settings
- Verify symmetric NAT not blocking
- May need TURN server

### Poor Quality
- Check network bandwidth
- Consider lowering video resolution
- Adjust video bitrate constraints
